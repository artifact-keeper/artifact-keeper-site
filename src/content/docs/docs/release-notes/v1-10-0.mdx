title: v1.10.x
description: Container image builder, external findings ingestion, AWS ECR and CodeArtifact upstream auth, sixteen security fixes, and API token repository-scope hardening in 1.10.2
---

The 1.10 line is a large release: 232 milestone items, roughly twice the size of 1.9.0. It adds a server-side container image builder and inspector ([#4034](https://github.com/artifact-keeper/artifact-keeper/issues/4034)), an ingestion endpoint that lets any out-of-tree scanner feed the existing policy gates ([#3411](https://github.com/artifact-keeper/artifact-keeper/issues/3411)), and upstream authentication to Amazon ECR and AWS CodeArtifact ([#1559](https://github.com/artifact-keeper/artifact-keeper/issues/1559)), plus sixteen security fixes and a long run of proxy, format and storage-accounting corrections. The latest patch is **1.10.2**, a security release that hardens API token repository scoping (GHSA-qh2h-m7hp-27pc).

:::caution[Read the upgrade notes before you deploy]
1.10.0 deliberately refuses several requests that 1.9.x accepted (storage GC without `dry_run`, anonymous `/v2` pulls with guest access off, Swagger UI without `ENABLE_SWAGGER=true`), and 1.10.2 tightens API token creation and scopes. Automation that relied on the old behaviour will start failing immediately after upgrade. Two admin backfills should also be run once the 1.10.0 migrations finish.
:::

## Upgrading

### Migrations

- **1.10.0 runs ten migrations on start-up: 210, 212, 214 through 221.** All are additive and none blocks reads or writes, but **migration 215 is a full-table aggregate over both proxy tables inside its own transaction**. On an instance with a busy proxy and a long retention window, budget seconds to minutes of extra start-up time on the upgrade that applies it ([#3577](https://github.com/artifact-keeper/artifact-keeper/issues/3577)).
- **1.10.1 has no schema migrations.**
- **1.10.2 adds migrations 235 and 237.** Migration 237 runs with a 5-second lock timeout and fails fast under lock contention; if the upgrade fails on a lock timeout, retry when the table is quieter. It is safe to re-run. It also marks repository tokens that had already lost every repository as deny-all, using the audit log.

### Storage GC requires `dry_run` (1.10.0)

**`POST /api/v1/admin/storage-gc` and `POST /api/v1/repositories/{key}/storage-gc` now require `dry_run` in the body and reject unknown fields, answering `422` and deleting nothing** ([#3501](https://github.com/artifact-keeper/artifact-keeper/issues/3501)). Previously `dry_run` was optional and defaulted to `false`, so an empty `{}`, or a misspelling such as `dryRun` or `dryrun`, performed a live, irreversible delete. Automation posting an empty body must now send `{"dry_run": false}` explicitly to keep running live GC. **`ak admin storage-gc run` without `--dry-run` sends `{}` and cannot run a live pass until a CLI release ships**; `--dry-run` keeps working, and the web UI's storage panel is unaffected.

### Post-upgrade backfills and SQL (1.10.0)

- **Run `POST /api/v1/admin/packages/backfill` once** ([#3659](https://github.com/artifact-keeper/artifact-keeper/issues/3659), [#3660](https://github.com/artifact-keeper/artifact-keeper/issues/3660)). Fifteen hosted format handlers (alpine, cargo, chef, cocoapods, conda, goproxy, huggingface, jetbrains, protobuf, pub, rpm, sbt, swift, terraform, vscode) wrote artifacts without registering the package, so those uploads were missing from Packages. The endpoint is idempotent and safe to re-run, but synchronous, so pick a quiet window on a large instance. Catalog rows whose artifacts are all gone also stop appearing.
- **Run `POST /api/v1/admin/storage/ledger/backfill` only if this database was ever restored from a backup** ([#3650](https://github.com/artifact-keeper/artifact-keeper/issues/3650)). A restore bypasses the triggers that maintain `repository_usage_ledger`, so `total_storage_bytes` reflected only writes since the restore. The recompute is idempotent and reports zero drift on a healthy instance; running GC first is safe.
- **NuGet instances need one SQL run** ([#3976](https://github.com/artifact-keeper/artifact-keeper/issues/3976)). Pushes registered a second, lowercased, metadata-less catalog row. New pushes write one row; the idempotent SQL in [#3976](https://github.com/artifact-keeper/artifact-keeper/issues/3976) merges existing twins into the row with the published casing.

### Behaviour changes in 1.10.0

- **`AK_GUEST_ACCESS_ENABLED=false` now applies to OCI `/v2`** ([#3854](https://github.com/artifact-keeper/artifact-keeper/issues/3854)). Previously an unauthenticated `docker pull` of a `public` repository succeeded even with guest access off. With the default (`true`) nothing changes. With it off, repositories that were `public` before the flag was set lose anonymous pulls; stored visibility is untouched and re-enabling the flag restores it. Refusals now carry a `Bearer` challenge pointing at `/v2/token`; `docker login` fixes a pipeline that breaks.
- **Swagger UI and the OpenAPI document are opt-in** ([#3489](https://github.com/artifact-keeper/artifact-keeper/issues/3489)). `GET /swagger-ui/` and `GET /api/v1/openapi.json` are mounted only when `ENABLE_SWAGGER=true`. They were previously served unauthenticated whenever `ENVIRONMENT` was not `production` (the default is `development`), and even `ENABLE_SWAGGER=false` turned them on. `ENVIRONMENT` no longer affects either; without the flag they return `404`.
- **`auth.admin_break_glass_enabled` is removed from the anonymous `GET /api/v1/system/config`** and is admin-only. The login page uses `local_login_enabled`, and `?fallback=local` remains the admin recovery route.
- **Scans that reported zero findings start reporting real ones** ([#3603](https://github.com/artifact-keeper/artifact-keeper/issues/3603), [#4035](https://github.com/artifact-keeper/artifact-keeper/issues/4035)). Hosted PyPI sdists, RubyGems, Cargo and NuGet (including the `chocolatey` and `powershell` aliases) uploads, and `.conda` / `.tar.bz2` packages, were stored as `completed` scans with zero findings because the engine cataloged nothing; for example `rack@2.0.7` goes from 0 findings to 35. Existing `scan_results` are not rewritten; the new verdict appears on the next scan. **Previously passing gates will begin to block artifacts that were always vulnerable**, and anything promoted under a zero-finding result on these formats should be rescanned deliberately.
- **Quarantine can no longer be enabled on a Remote or Virtual repository**; `PATCH /api/v1/repositories/{key}` answers `400` ([#3647](https://github.com/artifact-keeper/artifact-keeper/issues/3647)). Repositories that already have it are left as set and warned about at start-up and on API reads. Turn it off with `{"quarantine_enabled": false}` and enable it on the hosted repository instead.
- **SBOM mutations require the repository `write`/`delete` action** ([#3824](https://github.com/artifact-keeper/artifact-keeper/issues/3824), GHSA-ww52-pmcg-f53c). Members without `delete` can no longer delete an SBOM, and non-members can no longer generate or convert one on a public repository.
- **Lifecycle policy create and update reject an unrecognised `config` key with `422`** ([#2024](https://github.com/artifact-keeper/artifact-keeper/issues/2024)). Policies already stored with a stray key keep running.
- **`GET /api/v1/peers/{id}/repositories` returns subscription objects, not bare UUIDs** ([#3575](https://github.com/artifact-keeper/artifact-keeper/issues/3575)). Read `.repository_id` from each element and regenerate SDKs from the published spec.
- **A Maven PUT of a resolved unique (timestamped) snapshot answers `409`** ([#3839](https://github.com/artifact-keeper/artifact-keeper/issues/3839)). Non-unique snapshots still republish in place.
- **Scan-on-proxy now gates VSIX delivery on `vscode` remotes** ([#3254](https://github.com/artifact-keeper/artifact-keeper/issues/3254), [#3255](https://github.com/artifact-keeper/artifact-keeper/issues/3255), [#3256](https://github.com/artifact-keeper/artifact-keeper/issues/3256)). Under `fail_closed` an inconclusive scan answers `423`; an unrecognised `targetPlatform` is `400`.
- **Token exchanges return shorter-lived bearers** ([#3460](https://github.com/artifact-keeper/artifact-keeper/issues/3460), [#3625](https://github.com/artifact-keeper/artifact-keeper/issues/3625), [#3548](https://github.com/artifact-keeper/artifact-keeper/issues/3548), [#3820](https://github.com/artifact-keeper/artifact-keeper/issues/3820)). Minted tokens are capped at the presenting credential's expiry; a client that hardcodes a 30-minute refresh interval will start seeing `401`s.
- **Error message text on `500`s no longer includes internal detail** ([#3718](https://github.com/artifact-keeper/artifact-keeper/issues/3718), [#3761](https://github.com/artifact-keeper/artifact-keeper/issues/3761)). Status codes and envelopes are unchanged; anything scraping detail from a 500 body must read the server log instead.
- **Swift releases and JetBrains plugins published through the multipart paths are corrupt on disk and must be republished** ([#3595](https://github.com/artifact-keeper/artifact-keeper/issues/3595), [#3848](https://github.com/artifact-keeper/artifact-keeper/issues/3848)). The stored checksum matches the corruption, so nothing detects it automatically. **Hosted Ansible collections published earlier must be re-published** to advertise their dependencies ([#3600](https://github.com/artifact-keeper/artifact-keeper/issues/3600)).
- **The Windows release asset is now `artifact-keeper-windows-amd64.zip`**, replacing the bare `.exe` ([#3637](https://github.com/artifact-keeper/artifact-keeper/issues/3637)). Installers pinned to the `.exe` URL must unzip. Unix targets are unchanged.
- **Proxy cache-hit counters will step up** for fourteen formats that previously counted nothing ([#3649](https://github.com/artifact-keeper/artifact-keeper/issues/3649)). This is a measurement correction, not new traffic.
- **The first proxied pull of each artifact after upgrading re-scans once** under scan-on-proxy, then reuses the stored verdict ([#4019](https://github.com/artifact-keeper/artifact-keeper/issues/4019)).
- **Re-running a Nexus raw/generic migration repairs doubled repository-key paths** ([#3654](https://github.com/artifact-keeper/artifact-keeper/issues/3654)); the old doubled download URLs `404` afterwards by design.
- **Deploy `artifact-keeper-web` 1.10.0 alongside the backend.**

### Behaviour changes in 1.10.1

- **Advisory feed outages now grade scans `partial`** ([#4080](https://github.com/artifact-keeper/artifact-keeper/issues/4080)). Findings are unchanged and no scan fails, but alerting or gating on `scan_completeness = complete` will see these scans. Deployments with no GitHub token configured are not affected by the GitHub feed.
- **Repository format strings changed to their underscored names** ([#4085](https://github.com/artifact-keeper/artifact-keeper/issues/4085)). `conda_native`, `wasm_oci` and `helm_oci` were served as `condanative`, `wasmoci` and `helmoci`. Clients matching on the old spellings must switch.
- **`JWT_SECRET` entropy is judged differently** ([#4211](https://github.com/artifact-keeper/artifact-keeper/issues/4211)). Hex secrets are accepted again (see below), but a secret made of a short repeated string is judged on a single copy and can now be refused even if it passed before.

### Behaviour changes in 1.10.2

Some 1.10.2 fixes intentionally refuse requests that 1.10.1 accepted.

- **Token creation is stricter.** All token-mint endpoints reject unknown JSON fields with `400`, and malformed bodies return `400` rather than `422`. An empty or non-restricting `repo_selector`, and a service-account `repository_ids: []`, are refused. A repository-restricted token (or a session exchanged from one) that names a selector or `repository_ids` for the new token gets `403`; with neither, the child inherits the restriction, and a restricted token whose restriction matches nothing cannot mint at all.
- **Existing selectors fail closed.** A token whose stored selector is unparseable or contains an unrecognised key now reaches no repositories, and its holder sees `404` where it used to succeed. Re-mint it with a corrected selector. A restricted token whose repositories have all been deleted also denies everything.
- **New scope requirements.** Repository management needs `write:repositories`. The npm scope policy, egress proxy and upstream-test reads need `read:repositories`, and the upstream test also needs repository admin. Deleting a repository needs `delete:repositories`; deleting an artifact or cancelling a chunked upload needs `delete:artifacts`. Webhook list, fetch and deliveries need `read:repositories` plus a read grant. The web UI's "Write" token type maps to `write:artifacts`, which does not cover repository management, so mint `write:repositories` explicitly for that.
- **Admins presenting a repository-scoped token are confined** to that scope in repository and package listings.

:::caution[Review and rotate tokens after upgrading to 1.10.2]
Tokens minted through a repository-restricted token before 1.10.2 may be unrestricted, and nothing records which token minted them. Personal tokens created with a repository scope through the web UI before 1.10.2 were issued unrestricted, and the upgrade does not fix them retroactively. Review and rotate tokens created by automation that authenticates with a restricted token, and UI-scoped personal tokens. A service-account token minted with an explicit `repository_ids` list whose repositories were all deleted before the upgrade cannot be told apart from an unrestricted one; an administrator should review and revoke it.
:::

## Highlights

### New features

- **Server-side container image builder and inspector** ([#4034](https://github.com/artifact-keeper/artifact-keeper/issues/4034)).
- **External findings ingestion.** Out-of-tree scanners can post findings through `POST /api/v1/security/findings/external`, feeding the same download gates, artifact scores and promotion gates as the built-in adapters ([#3411](https://github.com/artifact-keeper/artifact-keeper/issues/3411)). It requires admin plus a dedicated `write:findings` scope. Rows are written already `completed` under scan type `external` (migration 220), with the vendor in `source` and `scanner_version`. `GET /security/scans` accepts a `scan_type` filter and findings accept `severity`, `source` and `cve_id`; unknown values are a `400` ([#3410](https://github.com/artifact-keeper/artifact-keeper/issues/3410)).
- **AWS ECR and CodeArtifact upstream auth.** Remote repositories authenticate through the process's own AWS identity, with tokens cached, re-minted before expiry and never persisted ([#1559](https://github.com/artifact-keeper/artifact-keeper/issues/1559)). The recommended Kubernetes deployment stores no AWS secret.
- **API token expiration policy.** Administrators can require new tokens to expire, bound the range and default an omitted expiry ([#3460](https://github.com/artifact-keeper/artifact-keeper/issues/3460), [#3625](https://github.com/artifact-keeper/artifact-keeper/issues/3625), migration 216). Enforcement is mint-time only and seeded as `require_expiration: false`; existing tokens keep working. The policy endpoint reports live never-expiring tokens by holder.
- **Stable SAML slugs.** A SAML configuration can be addressed by an operator-chosen `slug`, so a rebuilt deployment keeps its ACS URL ([#2583](https://github.com/artifact-keeper/artifact-keeper/issues/2583), migration 218). Existing UUID URLs keep resolving.
- **Lifecycle policy exclusions.** An `exclude` block names versions and patterns a policy must never delete; dry runs report `bytes_matched` ([#2024](https://github.com/artifact-keeper/artifact-keeper/issues/2024), migration 217).
- **Cargo publish-age gate.** Cargo remotes can hold newly published crate versions behind the same publish-age gate as npm, PyPI and VS Code, on both the sparse index and `.crate` downloads ([#3480](https://github.com/artifact-keeper/artifact-keeper/issues/3480), contributed by @cazlo in [#3483](https://github.com/artifact-keeper/artifact-keeper/issues/3483)).
- **Jupyter support.** PyPI repositories serve the legacy JSON API and XML-RPC `browse`, so JupyterLab 4's Extension Manager works against a private index ([#3783](https://github.com/artifact-keeper/artifact-keeper/issues/3783)); `jupyter` is a new PyPI alias format ([#3784](https://github.com/artifact-keeper/artifact-keeper/issues/3784), migration 212).
- **New configuration.** `OPENSEARCH_INDEX_PREFIX` lets several instances share an OpenSearch cluster ([#3669](https://github.com/artifact-keeper/artifact-keeper/issues/3669)); unset keeps the historical index names, while setting it on an existing deployment points at a new index that repopulates in the background. `/search/quick` now uses OpenSearch when configured, with visibility enforced from PostgreSQL ([#3670](https://github.com/artifact-keeper/artifact-keeper/issues/3670)). `INITIAL_ADMIN_PASSWORD` or `INITIAL_ADMIN_PASSWORD_FILE` presets the first-boot admin password ([#2803](https://github.com/artifact-keeper/artifact-keeper/issues/2803)). `NPM_ATTESTATION_NEGATIVE_CACHE_TTL_SECS` (default 3600) caches negative npm attestation lookups ([#3764](https://github.com/artifact-keeper/artifact-keeper/issues/3764)). The OCI virtual negative cache window and size are configurable with unchanged defaults ([#1424](https://github.com/artifact-keeper/artifact-keeper/issues/1424)). `INCUS_SCANNER_ENABLED=false` keeps the Incus scanner out entirely ([#3874](https://github.com/artifact-keeper/artifact-keeper/issues/3874)).
- **OpenShift `restricted-v2`.** The backend and openscap images run as an arbitrary high UID ([#3434](https://github.com/artifact-keeper/artifact-keeper/issues/3434)). The scanner-adapter image is not converted yet.
- **Release supply chain.** Every published release digest is verified for a build-provenance attestation and cosign signature ([#3519](https://github.com/artifact-keeper/artifact-keeper/issues/3519)), and a CI gate rejects new migrations that would block writes on a hot table ([#3864](https://github.com/artifact-keeper/artifact-keeper/issues/3864), [#2524](https://github.com/artifact-keeper/artifact-keeper/issues/2524)). Release binaries are about 15% smaller ([#3637](https://github.com/artifact-keeper/artifact-keeper/issues/3637)).

### Security

Sixteen fixes, plus the scanning-coverage fixes ([#3603](https://github.com/artifact-keeper/artifact-keeper/issues/3603), [#4035](https://github.com/artifact-keeper/artifact-keeper/issues/4035)) described under Upgrading.

- **Logout now revokes the refresh token** ([#3824](https://github.com/artifact-keeper/artifact-keeper/issues/3824), GHSA-965p-gcgh-67vf). `/api/v1/auth/logout` was mounted without the optional-auth middleware, so a captured 7-day refresh token stayed usable after logout.
- **Credential exchanges no longer outlive the presenting credential** ([#3460](https://github.com/artifact-keeper/artifact-keeper/issues/3460), [#3625](https://github.com/artifact-keeper/artifact-keeper/issues/3625), [#3548](https://github.com/artifact-keeper/artifact-keeper/issues/3548), [#3820](https://github.com/artifact-keeper/artifact-keeper/issues/3820)). The three OCI `/v2/token` arms, Conan `users/authenticate` and the CI token exchange minted full-lifetime JWTs; the Conan JWT could be re-presented indefinitely as a self-renewing chain.
- **Anonymous `/v2` pulls honour guest access** ([#3854](https://github.com/artifact-keeper/artifact-keeper/issues/3854)), and **SBOM mutations require write/delete** ([#3824](https://github.com/artifact-keeper/artifact-keeper/issues/3824), GHSA-ww52-pmcg-f53c).
- **Webhook reads honour an API token's repository scope** ([#3715](https://github.com/artifact-keeper/artifact-keeper/issues/3715)).
- **Path validation on thirteen native write paths** (terraform, cargo, helm, pypi, npm, goproxy, nuget, cran, composer, rubygems, jetbrains, conan, ansible): names containing `..`, `//`, backslashes, NULs or percent-encoded variants are rejected with `400`, including Conan's `%2e%2f` bypass ([#3824](https://github.com/artifact-keeper/artifact-keeper/issues/3824), GHSA-vcq6-8hxw-4q67). **HuggingFace `x-filename` path traversal**, which could overwrite files on the filesystem backend, is rejected ([#3824](https://github.com/artifact-keeper/artifact-keeper/issues/3824), GHSA-6wjw-gcvx-3q58).
- **Visibility timing oracle closed.** Confirmed misses are cached like hits, so response timing no longer reveals whether an out-of-scope repository exists ([#3750](https://github.com/artifact-keeper/artifact-keeper/issues/3750)).
- **Internal detail removed from error text**: the `/v2` resolver no longer echoes pool state or table names to anonymous callers ([#3761](https://github.com/artifact-keeper/artifact-keeper/issues/3761)), and 68 sites across eighteen formats no longer render storage keys, OS errors or upstream URLs ([#3718](https://github.com/artifact-keeper/artifact-keeper/issues/3718)).
- **Swagger UI and the break-glass advertisement** are no longer exposed anonymously ([#3489](https://github.com/artifact-keeper/artifact-keeper/issues/3489)).
- **Dependency CVEs**: `cryptoki` 0.12.1 for RUSTSEC-2026-0286 (GHSA-r6vc-97x9-63vv), inert without an HSM; `rustls` 0.23.45 for RUSTSEC-2026-0285 ([#3878](https://github.com/artifact-keeper/artifact-keeper/issues/3878)); and CVE-2026-84445 in gRPC-Go, unreachable here but rebuilt: bundled grype's grpc override moves to v1.83.2 and the scanner adapter is published as 1.2.11 on trivy 0.74.0-r3 ([#3790](https://github.com/artifact-keeper/artifact-keeper/issues/3790), [#3792](https://github.com/artifact-keeper/artifact-keeper/issues/3792)).

### Notable fixes

- **Proxy correctness.** Concurrent cold fetches of a large artifact no longer hand waiting clients a truncated body under a `200` ([#3363](https://github.com/artifact-keeper/artifact-keeper/issues/3363)). Cache entries are classified against the repository's real format, ending perpetual re-fetches of immutable content ([#3556](https://github.com/artifact-keeper/artifact-keeper/issues/3556)). Upstream `410 Gone` is negative-cached ([#3749](https://github.com/artifact-keeper/artifact-keeper/issues/3749)), and the OCI virtual resolver no longer negative-caches a throttled member ([#3836](https://github.com/artifact-keeper/artifact-keeper/issues/3836)).
- **OCI.** Blob `GET` honours `Range` so interrupted layer downloads resume ([#3586](https://github.com/artifact-keeper/artifact-keeper/issues/3586)). `HEAD` on an uncached remote blob over 8 MiB no longer reports `404` ([#3605](https://github.com/artifact-keeper/artifact-keeper/issues/3605)). Tagged images pulled through a Virtual reach the packages catalog ([#3602](https://github.com/artifact-keeper/artifact-keeper/issues/3602)), and proxied multi-arch tags report the image size ([#3601](https://github.com/artifact-keeper/artifact-keeper/issues/3601)).
- **Formats.** NuGet virtuals federate their members, fixing `dotnet restore` NU1102 failures ([#3980](https://github.com/artifact-keeper/artifact-keeper/issues/3980)). Go virtual `@v/list` collates every readable member ([#833](https://github.com/artifact-keeper/artifact-keeper/issues/833)). Helm remotes no longer double the upstream subpath ([#3705](https://github.com/artifact-keeper/artifact-keeper/issues/3705)). Debian remotes stream large `.deb` files under `dists/` ([#3596](https://github.com/artifact-keeper/artifact-keeper/issues/3596)) and RPM repodata is streamed ([#3486](https://github.com/artifact-keeper/artifact-keeper/issues/3486), [#2622](https://github.com/artifact-keeper/artifact-keeper/issues/2622)). Authenticated Terraform mirrors hand out ticketed archive URLs ([#3588](https://github.com/artifact-keeper/artifact-keeper/issues/3588)). Concurrent Maven snapshot uploads no longer `500` ([#3587](https://github.com/artifact-keeper/artifact-keeper/issues/3587)). Curation runs for `poetry`, `jupyter`, `yarn` and `pnpm` staging repositories ([#3787](https://github.com/artifact-keeper/artifact-keeper/issues/3787)). Cargo dependency scanning works again ([#3699](https://github.com/artifact-keeper/artifact-keeper/issues/3699), [#3690](https://github.com/artifact-keeper/artifact-keeper/issues/3690)). The web UI upload is no longer refused by the CSRF check ([#3592](https://github.com/artifact-keeper/artifact-keeper/issues/3592)).
- **Storage.** Alibaba Cloud OSS works as a backend, with automatic detection and an optional `S3_PROVIDER` override ([#3593](https://github.com/artifact-keeper/artifact-keeper/issues/3593), [#3594](https://github.com/artifact-keeper/artifact-keeper/issues/3594)). A custom `S3_ENDPOINT` on AWS can boot on the instance profile via a one-second IMDSv2 probe; `S3_USE_INSTANCE_PROFILE=true` opts in explicitly and `AWS_EC2_METADATA_DISABLED=true` restores the old error ([#4060](https://github.com/artifact-keeper/artifact-keeper/issues/4060)). OCI objects orphaned by a repository delete are reclaimed after a 24-hour grace window ([#3733](https://github.com/artifact-keeper/artifact-keeper/issues/3733), migration 219). Repository deletes no longer deadlock with GC or stats recompute ([#4004](https://github.com/artifact-keeper/artifact-keeper/issues/4004), [#3957](https://github.com/artifact-keeper/artifact-keeper/issues/3957)). Proxy-cached bytes appear in the per-repository breakdown ([#3577](https://github.com/artifact-keeper/artifact-keeper/issues/3577), migrations 210 and 215). The GC tick's singleton lease now covers all four workloads ([#3503](https://github.com/artifact-keeper/artifact-keeper/issues/3503), [#3502](https://github.com/artifact-keeper/artifact-keeper/issues/3502)). Chunked-upload completion no longer rewrites stored objects, and the filesystem backend's `put_file` is stage-and-rename ([#3517](https://github.com/artifact-keeper/artifact-keeper/issues/3517), [#3530](https://github.com/artifact-keeper/artifact-keeper/issues/3530)).
- **Auth.** The keyless CI token exchange resolves its provider from the assertion's `iss`; `provider_id` is still accepted ([#3548](https://github.com/artifact-keeper/artifact-keeper/issues/3548)). The OIDC boot reconcile keeps `attribute_mapping` keys the environment never set ([#3507](https://github.com/artifact-keeper/artifact-keeper/issues/3507)). A first federated or CI login no longer returns an already-invalidated access token ([#3946](https://github.com/artifact-keeper/artifact-keeper/issues/3946)).
- **Webhooks.** `artifact.uploaded` and `artifact.deleted` webhooks and email subscriptions now actually fire, including for native publishes ([#3411](https://github.com/artifact-keeper/artifact-keeper/issues/3411)).
- **Virtual listings.** The Packages page and Docker grouped tag view aggregate member content ([#3532](https://github.com/artifact-keeper/artifact-keeper/issues/3532)).
- **Nexus migration.** No longer super-linear in component count, with accurate counters and reports ([#3590](https://github.com/artifact-keeper/artifact-keeper/issues/3590), [#3512](https://github.com/artifact-keeper/artifact-keeper/issues/3512)); tolerant of transient source failures with redacted retry logs ([#3569](https://github.com/artifact-keeper/artifact-keeper/issues/3569)); cancellations logged as cancelled ([#3498](https://github.com/artifact-keeper/artifact-keeper/issues/3498)).

## Patches

### 1.10.2 (2026-10-02)

Security release for API token scoping, published with advisory [GHSA-qh2h-m7hp-27pc](https://github.com/artifact-keeper/artifact-keeper/security/advisories/GHSA-qh2h-m7hp-27pc). Adds migrations 235 and 237; see the Upgrading section for the behaviour changes and token review.

- **A repository-scoped token can no longer mint a wider token.** Mint endpoints checked permission scopes but not repository scope; a child now inherits its parent's repositories ([#4227](https://github.com/artifact-keeper/artifact-keeper/issues/4227), [#4225](https://github.com/artifact-keeper/artifact-keeper/issues/4225)).
- **Repository selectors fail closed**, and token-creation requests refuse unknown fields, so a misspelled `repo_selector` can no longer mint an unrestricted token ([#4227](https://github.com/artifact-keeper/artifact-keeper/issues/4227), [#4226](https://github.com/artifact-keeper/artifact-keeper/issues/4226)).
- **Personal tokens honour their repository selector.** The web UI's Access Tokens page sent a `repo_selector` the API silently dropped ([#4224](https://github.com/artifact-keeper/artifact-keeper/issues/4224), [#4219](https://github.com/artifact-keeper/artifact-keeper/issues/4219)).
- **Deleting repositories can only narrow a token.** A token pinned to repositories that were all deleted now denies everything instead of becoming unrestricted ([#4265](https://github.com/artifact-keeper/artifact-keeper/issues/4265), [#4271](https://github.com/artifact-keeper/artifact-keeper/issues/4271), [#4228](https://github.com/artifact-keeper/artifact-keeper/issues/4228)).
- **Repository-management endpoints accept token scopes** (`write:repositories`, `read:repositories`, `delete:repositories`, `delete:artifacts`); previously only session logins and `admin`/`*` tokens could call them ([#4265](https://github.com/artifact-keeper/artifact-keeper/issues/4265), [#4271](https://github.com/artifact-keeper/artifact-keeper/issues/4271), [#3831](https://github.com/artifact-keeper/artifact-keeper/issues/3831)).
- **Webhook reads match the listing**: fetch by id needs the same access, reads need `read:repositories`, and custom header values are redacted as `***` ([#4265](https://github.com/artifact-keeper/artifact-keeper/issues/4265), [#4271](https://github.com/artifact-keeper/artifact-keeper/issues/4271), [#3901](https://github.com/artifact-keeper/artifact-keeper/issues/3901)).
- **wasmtime 36.0.16** for RUSTSEC-2026-0314 and RUSTSEC-2026-0316, where a WASM plugin could exceed its fuel limit or panic the host ([#4332](https://github.com/artifact-keeper/artifact-keeper/issues/4332)).
- **Natively pushed conda packages are scanned on upload** ([#4167](https://github.com/artifact-keeper/artifact-keeper/issues/4167), [#4159](https://github.com/artifact-keeper/artifact-keeper/issues/4159)).
- **Composer can no longer stall the shared metadata proxy** for every format through concurrent anonymous lookups ([#4170](https://github.com/artifact-keeper/artifact-keeper/issues/4170), [#4162](https://github.com/artifact-keeper/artifact-keeper/issues/4162)).

### 1.10.1 (2026-09-24)

No schema migrations.

- **Hex `JWT_SECRET` values work again** ([#4211](https://github.com/artifact-keeper/artifact-keeper/issues/4211)). Since 1.7.0 about one in four `openssl rand -hex 32` secrets was refused as low entropy. Entropy is now estimated per character class (4 bits for hex, 6 for base64) against a 128-bit bar; the shortest accepted hex secret is 32 characters. Workarounds already in place keep working.
- **Advisory scanning fixes**, all present in 1.8.2, 1.9.0 and 1.10.0, from an OSV.dev batch response read out of query order: a vulnerability in one dependency was cached against every dependency in the batch for an hour ([#4079](https://github.com/artifact-keeper/artifact-keeper/issues/4079)); findings named the wrong dependency, affecting SBOMs and dedup keys ([#4081](https://github.com/artifact-keeper/artifact-keeper/issues/4081)); and feed outages were recorded as clean, complete scans and are now `partial` ([#4080](https://github.com/artifact-keeper/artifact-keeper/issues/4080)).
- **Format strings** `conda_native`, `wasm_oci` and `helm_oci` are returned with underscores, so the UI no longer shows them as `GENERIC` and round-tripping no longer fails with `400 Invalid format` ([#4085](https://github.com/artifact-keeper/artifact-keeper/issues/4085)).
