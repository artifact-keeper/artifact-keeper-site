---

The 1.11 line is a large release: about 340 changelog entries in 1.11.0 alone. It adds hosted Arch Linux (pacman) and Bazel module repositories, a third repository visibility (`internal`), lifecycle policies assigned to chosen repositories, scan-on-proxy for Maven, Gradle, sbt, NuGet, Cargo and conda, private conda channels that pixi and rattler can use end to end, Ed25519-signed webhooks, Kubernetes ServiceAccount image pulls, and storage quotas enforced on every native publish. Ten patch releases followed, mostly security hardening, replication fixes and conda work. The latest patch is **1.11.10**, and it is the version to deploy.

1.11.0 also contains every fix shipped in 1.10.1 and 1.10.2. From 1.10.2, the repository-management token scopes ([#3831](https://github.com/artifact-keeper/artifact-keeper/issues/3831)), the webhook read gate ([#3901](https://github.com/artifact-keeper/artifact-keeper/issues/3901)), the four token-restriction fixes ([#4219](https://github.com/artifact-keeper/artifact-keeper/issues/4219), [#4225](https://github.com/artifact-keeper/artifact-keeper/issues/4225), [#4226](https://github.com/artifact-keeper/artifact-keeper/issues/4226), [#4228](https://github.com/artifact-keeper/artifact-keeper/issues/4228)), the conda native-PUT scan ([#4159](https://github.com/artifact-keeper/artifact-keeper/issues/4159)), the Composer metadata deadlock ([#4170](https://github.com/artifact-keeper/artifact-keeper/issues/4170)) and wasmtime 36.0.16 ([#4332](https://github.com/artifact-keeper/artifact-keeper/issues/4332)) are already deployed.

:::caution[Read the upgrade notes before you deploy]
1.11.0 runs 58 migrations from 1.10.2 (60 from 1.10.0 or 1.10.1), and **migration 233 requires stopping every old backend replica before it runs**. Several endpoints that used to accept requests now refuse them, including every native publish into a repository already over its quota. Read **Upgrading** below in full.
:::

## Upgrading

### Stop all replicas before migration 233 (1.11.0)

- **Lifecycle policies are now scoped by explicit repository assignments, and an older binary misreads the new scope as "every repository"** ([#3794](https://github.com/artifact-keeper/artifact-keeper/issues/3794), migration 233). A policy now carries `applies_to_all` plus a list of assigned repositories. The migration preserves behaviour (a null `repository_id` becomes `applies_to_all = true`; a single-repository policy gets one assignment), but as soon as a 1.11 replica creates a dormant or multi-repository policy, or a repository is deleted, an old replica or lifecycle scheduler still running reads that policy as global and can delete artifacts across the whole instance.
- **Scale the backend to zero (or otherwise stop every old pod and scheduler) before upgrading. Do not do a rolling or mixed-version deploy.** Helm upgrades are rolling by default.
- **Creating a policy without `repository_id` now creates a dormant policy that deletes nothing**, not a global one. CLI, Terraform and other clients that relied on the old default must send `applies_to_all: true`. Deleting a repository no longer deletes its single-repository policies; it leaves them dormant.

### Migrations (1.11.0)

Upgrading from 1.10.2 runs 58 migrations (222 to 289, less unused numbers and 235/237, which shipped in 1.10.2); from 1.10.0 or 1.10.1, 60. Every 1.11 patch keeps the schema at **289**. The ones to plan for:

- **228** backfills `artifacts.origin` in resumable batches outside a transaction; its time grows with the number of artifacts ([#4050](https://github.com/artifact-keeper/artifact-keeper/issues/4050)). 227 to 230 are the rest of the origin work (230 builds an index `CONCURRENTLY`; see below).
- **268** creates `oci_manifests`; a background task at boot backfills it from storage. Nothing reads it yet, but a 1.10.x replica writes no rows for its pushes, which is another reason to stop old replicas ([#4433](https://github.com/artifact-keeper/artifact-keeper/issues/4433)).
- **270, 271 and 284** rewrite origin rows in 5000-row batches with a 5-second `lock_timeout`: 270 re-labels Artifactory/Nexus imports as `migration` ([#4153](https://github.com/artifact-keeper/artifact-keeper/issues/4153)), 271 strips `user:password@` from the upstream URLs copied into `artifacts.origin` and `proxy_cache_artifacts`; the Remote's own `upstream_url` still holds them ([#4463](https://github.com/artifact-keeper/artifact-keeper/issues/4463)), 284 re-stamps staging uploads from `virtual` to `hosted` ([#4557](https://github.com/artifact-keeper/artifact-keeper/issues/4557)).
- **276** moves pacman file lists into their own table ([#4424](https://github.com/artifact-keeper/artifact-keeper/issues/4424)). It is forward-only: rolling back past it leaves `.files` with empty file lists.
- **277 to 283** re-key proxy download history ([#4539](https://github.com/artifact-keeper/artifact-keeper/issues/4539)). **279 takes `ACCESS EXCLUSIVE` on `proxy_cache_artifacts` and `proxy_download_statistics`** for a catalogue-only change; proxy serves wait at most its 5-second `lock_timeout`.
- **288** re-seeds `hosted_bytes` so OCI manifest rows no longer count toward usage ([#4483](https://github.com/artifact-keeper/artifact-keeper/issues/4483), [#4545](https://github.com/artifact-keeper/artifact-keeper/issues/4545)). **Expect `storage_used_bytes` on Docker repositories to drop.**
- **285 to 287 and 289** add columns: `builds.created_by` (builds from before the upgrade become administrator-only to change), download-ticket scope (tickets minted before the upgrade are refused), `components_cataloged`, and Incus `staged_parts`.
- **Concurrent index builds**: 230, 266, 272, 274, 281 and 283. 273 to 275 rebuild the scan-reuse index online and need disk space for both indexes until 275 runs. New in 1.11.0, startup drops an INVALID leftover from an interrupted concurrent build so the retry rebuilds it.
- **257** adds `kubernetes` CI OIDC providers ([#1246](https://github.com/artifact-keeper/artifact-keeper/issues/1246)). Rolling back makes such a provider act as `generic` (unrestricted, renewable tokens), so disable them before any rollback.

### Rollback (1.11.0, documented in 1.11.7)

- **Downgrading to 1.10.x after migration 233 is unsafe** unless lifecycle policy scopes are first reconciled by hand.
- **A 1.11.x database cannot serve a 1.10.x backend for OCI pushes** ([#4915](https://github.com/artifact-keeper/artifact-keeper/issues/4915)). Migration 243 replaced a unique key the 1.10.x upload path relies on, so after a rollback every `docker push` fails. The rollback guide in the repository (`docs/operations/rollback.md`) lists the releases that cannot be rolled back across.

### Requests that are now refused (1.11.0)

- **Storage quotas apply to every native format publish: `507`** ([#4422](https://github.com/artifact-keeper/artifact-keeper/issues/4422)). Previously only generic uploads, chunked uploads and `npm publish` checked `quota_bytes`. **A repository or project already over its quota refuses every publish that adds bytes after the upgrade.** Check usage against quotas first. Docker answers the registry envelope (`507`, `DENIED`); most other formats answer `507 QUOTA_EXCEEDED`. A publish that adds no bytes is always admitted. A manifest declaring a negative or absurd size is `400 MANIFEST_INVALID`. Promotions, migration imports, replication and proxy-cache fills are still not quota-checked ([#4546](https://github.com/artifact-keeper/artifact-keeper/issues/4546)).
- **Origin policies gate what a Remote serves, metadata included: `403`** ([#4506](https://github.com/artifact-keeper/artifact-keeper/issues/4506), [#4161](https://github.com/artifact-keeper/artifact-keeper/issues/4161)). Proxied content now carries origin `kind: proxy` and is evaluated against the Remote's own and global policies. **A global policy with `allowed_upstreams` that does not list a Remote's upstream, or with `allowed_kinds` that excludes `proxy`, now refuses every download from every Remote.** Review global origin policies before upgrading.
- **Six security advisories, four of which refuse requests that used to pass** ([#4588](https://github.com/artifact-keeper/artifact-keeper/issues/4588)). Eight REST mutation endpoints now check the caller's repository action (GHSA-mvmh-g8wm-r3cp): release-target link/unlink and email subscriptions need `admin`, label writes, image builds and proxy-scan rescans need `write`, rejecting a staged artifact needs promotion rights, peer connection probes are admin-only, and a build can be changed only by its creator or an admin. `PUT /api/v1/repositories/{key}/security` needs the `write:repositories` scope (GHSA-gvhj-8vg9-358g). Download tickets carry the minting credential's repository restriction, need `read:artifacts`, and pre-upgrade tickets are refused (GHSA-2mfv-xg68-gq4p); this also repairs ticket redemption, which had broken web UI `?ticket=` downloads and Terraform mirror archive URLs ([#3588](https://github.com/artifact-keeper/artifact-keeper/issues/3588)). An image-build package spec with a line break or control character is `400` (GHSA-59mx-6fq9-pp9p).
- **Stalled uploads are cut off with `408`, and a principal is capped at 64 uploads in flight with `429`** (GHSA-9f9r-c4w8-rjv9, [#4588](https://github.com/artifact-keeper/artifact-keeper/issues/4588), [#4609](https://github.com/artifact-keeper/artifact-keeper/issues/4609)). New knobs: `UPLOAD_MIN_PROGRESS_BYTES` (default 16384) per `UPLOAD_PROGRESS_WINDOW_SECS` (default 60), `UPLOAD_MAX_IN_FLIGHT_PER_PRINCIPAL` (default 64) and `UPLOAD_MEMORY_BUDGET_BYTES` (default half the cgroup memory limit); `0` disables each. Archive-parsing publish routes now answer a short body with `408 incomplete_body`, a full memory budget with `503` and `Retry-After`, and a full disk with `507`. **A `400` from these routes now always means the package itself is invalid.**
- **A virtual repository whose member fails answers `502` naming it, instead of a smaller index** ([#4192](https://github.com/artifact-keeper/artifact-keeper/issues/4192), [#4555](https://github.com/artifact-keeper/artifact-keeper/issues/4555), [#4508](https://github.com/artifact-keeper/artifact-keeper/issues/4508)). This covers Helm, CRAN, Hex, Bazel and conda merged metadata. A member that does not answer within `AK_VIRTUAL_MEMBER_METADATA_TIMEOUT_SECS` (default 20) is a failure. Set `virtual_metadata_partial: true` on a virtual to get the old partial merge, flagged by `X-AK-Partial-Members`. A member `404` is not a failure. A database failure while authorizing members is now a retryable `503 POOL_EXHAUSTED`, not a `404` that Gradle caches ([#4308](https://github.com/artifact-keeper/artifact-keeper/issues/4308)).
- **Scan-on-proxy now enforces on Remotes that already had it enabled**: Maven, Gradle, sbt, NuGet, Chocolatey, PowerShell and Cargo ([#4100](https://github.com/artifact-keeper/artifact-keeper/issues/4100), [#4102](https://github.com/artifact-keeper/artifact-keeper/issues/4102), [#4101](https://github.com/artifact-keeper/artifact-keeper/issues/4101)), the VS Code legacy route ([#4098](https://github.com/artifact-keeper/artifact-keeper/issues/4098)) and conda ([#4585](https://github.com/artifact-keeper/artifact-keeper/issues/4585)). A vulnerable package is `403 scan_blocked`; under `fail_closed` an unscannable one is `423`. **These pulls were served unscanned before, so gates that were never exercised can start blocking.** Conda grading changed so `fail_closed` is usable against conda-forge ([#4594](https://github.com/artifact-keeper/artifact-keeper/issues/4594), [#4600](https://github.com/artifact-keeper/artifact-keeper/issues/4600)).
- **The generic download route refuses proxied files of an enforced format while the repository scans on proxy: `403 scan_on_proxy_route_required`** ([#4442](https://github.com/artifact-keeper/artifact-keeper/issues/4442)). Clients must switch to the format route named in the `handler` field. Ambiguous proxied paths (containing `?`, `#`, `;`, `\`, control characters or a stray `%`) are `400`, and an unreadable scan setting is a retryable `503` instead of streaming unscanned ([#4513](https://github.com/artifact-keeper/artifact-keeper/issues/4513)).
- **A CI OIDC credential can no longer mint an API token: `403`** ([#4314](https://github.com/artifact-keeper/artifact-keeper/issues/4314)). Pipelines must exchange a fresh CI token per job. An assertion whose `nbf` is more than 60 s in the future is `401` ([#4511](https://github.com/artifact-keeper/artifact-keeper/issues/4511)).
- **Lifecycle regexes are PostgreSQL regular expressions, and `\b` / `\B` are refused: `400`** ([#4461](https://github.com/artifact-keeper/artifact-keeper/issues/4461), [#4502](https://github.com/artifact-keeper/artifact-keeper/issues/4502), [#4504](https://github.com/artifact-keeper/artifact-keeper/issues/4504)). In PostgreSQL `\b` is a backspace, so `\bstable\b` protected nothing; use `\y` / `\Y`. Stored policies are not changed, but startup logs a WARN per offender and a live run refuses one whose exclusion would fail open. A lifecycle policy that cannot reclaim anything in a Remote answers `422` when assigned there ([#3734](https://github.com/artifact-keeper/artifact-keeper/issues/3734)).
- **Other refusals.** Creating a public repository while guest access is disabled is `400` instead of silently storing it private ([#3855](https://github.com/artifact-keeper/artifact-keeper/issues/3855)). Unknown webhook event names are `400`; existing webhooks with unknown names still never fire, so recreate them ([#4419](https://github.com/artifact-keeper/artifact-keeper/issues/4419)). Generic, chunked and multipart uploads refuse Remote (`405`) and Virtual (`400`) repositories ([#4420](https://github.com/artifact-keeper/artifact-keeper/issues/4420)). `PATCH` that moves a credentialed Remote to another origin is `409` ([#4467](https://github.com/artifact-keeper/artifact-keeper/issues/4467)). A Conan manifest that arrives before its files is `409` ([#4329](https://github.com/artifact-keeper/artifact-keeper/issues/4329)). Hex publish without a usable `CHECKSUM` is `422` ([#2904](https://github.com/artifact-keeper/artifact-keeper/issues/2904)). `POST /api/v1/signing/keys` with `key_type = ed25519` is `400`; use `key_type = gpg` with `algorithm = ed25519` ([#1326](https://github.com/artifact-keeper/artifact-keeper/issues/1326)). A multipart publish over `MAX_UPLOAD_SIZE` is `413`, and completing a chunked upload onto an occupied immutable path is `409` ([#3936](https://github.com/artifact-keeper/artifact-keeper/issues/3936), [#3924](https://github.com/artifact-keeper/artifact-keeper/issues/3924)). Duplicate scan-policy names on one repository are `409` ([#4558](https://github.com/artifact-keeper/artifact-keeper/issues/4558)). Terraform module uploads that are not ZIP or gzip tar are `400` ([#4590](https://github.com/artifact-keeper/artifact-keeper/issues/4590)).
- **Known-malicious packages are graded `Critical`** ([#3013](https://github.com/artifact-keeper/artifact-keeper/issues/3013)). OSV `MAL-*` advisories used to default to `Medium`, below a typical gate.

### Behaviour that changes without an error (1.11.0)

- **A credentialed Docker Hub Remote must add `"oci_trusted_bearer_realms": ["https://auth.docker.io"]`** ([#3591](https://github.com/artifact-keeper/artifact-keeper/issues/3591)), or pulls fall back to anonymous tokens. Split-host GitLab registries need the same.
- **A Remote's upstream credentials go only to its configured upstream's origin** (GHSA-24rf-2gv2-j47c, [#4588](https://github.com/artifact-keeper/artifact-keeper/issues/4588)). A credentialed Remote whose files are served from a different host than its index now gets `401`/`403` from that host. For split-host Cargo registries, set `index_upstream_url` and `upstream_url` separately.
- **Upstream credentials embedded in `upstream_url` are no longer returned by the API** and are stripped from stored origin records ([#4452](https://github.com/artifact-keeper/artifact-keeper/issues/4452), [#4463](https://github.com/artifact-keeper/artifact-keeper/issues/4463), migration 271). Rotate any such secret and move it to the encrypted upstream-auth fields.
- **Presigned redirects need `S3_PUBLIC_ENDPOINT` / `AZURE_STORAGE_PUBLIC_ENDPOINT`** when clients reach the object store through a different host than the backend ([#4417](https://github.com/artifact-keeper/artifact-keeper/issues/4417)). A malformed value stops the backend at startup.
- **A virtual repository's `storage_used_bytes` is now `0`**; the member total moves to `member_storage_used_bytes` ([#4423](https://github.com/artifact-keeper/artifact-keeper/issues/4423), [#4505](https://github.com/artifact-keeper/artifact-keeper/issues/4505)). Dashboards and older web UI/CLI builds show `0` until they read the new field.
- **The admin download report includes proxy serves, and `artifact_id` can be `null`** ([#4539](https://github.com/artifact-keeper/artifact-keeper/issues/4539), [#3844](https://github.com/artifact-keeper/artifact-keeper/issues/3844)). A client generated from the 1.10 spec that types `artifact_id` as required fails on such a page; pass `source=hosted` for the old listing. `total_downloads` in `/admin/stats` now includes proxy downloads (`proxy_download_count` is the breakdown).
- **`ak_http_request_duration_seconds` is a histogram; its `quantile` series are gone** ([#4434](https://github.com/artifact-keeper/artifact-keeper/issues/4434)). Use `histogram_quantile()` over `_bucket`.
- **`AK_GUEST_ACCESS_ENABLED`, when set, overrides the new runtime toggle** ([#867](https://github.com/artifact-keeper/artifact-keeper/issues/867)). The Helm chart must not set it.
- **Single-flight across replicas** ([#4532](https://github.com/artifact-keeper/artifact-keeper/issues/4532)): with `PROXY_SINGLEFLIGHT_ADVISORY_LOCKS_ENABLED=true`, keep `PROXY_SINGLEFLIGHT_LOCK_WAIT_TIMEOUT_SECS` (default 65) below your ingress read timeout (nginx-ingress: 60), and budget up to `PROXY_SINGLEFLIGHT_MAX_LOCK_WAITERS` (default 32) extra database connections per replica.
- **Severity counts use one definition**, so repository scores and grades can change on upgrade ([#4338](https://github.com/artifact-keeper/artifact-keeper/issues/4338)).
- **Maven unique snapshots are overwritable again** ([#4476](https://github.com/artifact-keeper/artifact-keeper/issues/4476)), reversing the `409` introduced in 1.10.0.
- **Version comparison honours epochs**, so curation rule matches change for epoch-bearing versions ([#4507](https://github.com/artifact-keeper/artifact-keeper/issues/4507)).
- **Lifecycle policies reclaim a Remote's proxy cache only when explicitly assigned** ([#3734](https://github.com/artifact-keeper/artifact-keeper/issues/3734)). `max_age_days` evicts by cache age, however often an entry is used; preview first.
- **npm tarballs on S3, GCS and Azure go to per-repository keys** ([#4293](https://github.com/artifact-keeper/artifact-keeper/issues/4293)). Existing tarballs stay where they are.
- **Lowering a cache TTL applies to entries already cached** ([#2667](https://github.com/artifact-keeper/artifact-keeper/issues/2667), [#3832](https://github.com/artifact-keeper/artifact-keeper/issues/3832)), and the ceiling is now ten years.
- **An OCI image deleted by digest stays deleted after a restart** ([#4450](https://github.com/artifact-keeper/artifact-keeper/issues/4450), [#4465](https://github.com/artifact-keeper/artifact-keeper/issues/4465)). One case remains: a migrated image pushed only by tag and deleted by digest on an older release; delete it again after the upgrade.
- **An OCI Remote whose upstream refuses sent credentials answers `502 DENIED`**, not `404 MANIFEST_UNKNOWN` ([#4453](https://github.com/artifact-keeper/artifact-keeper/issues/4453), [#4518](https://github.com/artifact-keeper/artifact-keeper/issues/4518), [#4527](https://github.com/artifact-keeper/artifact-keeper/issues/4527)).
- **The stock `docker-compose.yml` binds Postgres and OpenSearch to `127.0.0.1` only** and no longer publishes Trivy or OpenSCAP ([#4480](https://github.com/artifact-keeper/artifact-keeper/issues/4480)). It also ships no `JWT_SECRET` default. Publish those services explicitly if you relied on reaching them from another host.
- **The bundled `docker/init-dtrack.sh` grants `VIEW_POLICY_VIOLATION`**; if you provisioned the Dependency-Track team yourself, grant it there too, or policy violations answer `502` ([#4430](https://github.com/artifact-keeper/artifact-keeper/issues/4430)).
- **The bundles API is a preview** (`501` on export/import, [#4400](https://github.com/artifact-keeper/artifact-keeper/issues/4400)), and Remote/virtual pacman repositories are not supported yet ([#4407](https://github.com/artifact-keeper/artifact-keeper/issues/4407)).

### Upgrade notes from the patches

- **1.11.1: `allowed_cidrs` and audit IPs behind a proxy** (GHSA-59x8-r6jj-x95h, [#4681](https://github.com/artifact-keeper/artifact-keeper/issues/4681)). A client IP from `X-Forwarded-For` is no longer used for authorization or audit unless `XFF_TRUSTED_FOR_AUTHZ=true`. With it unset, `allowed_cidrs` grants do not match requests through a trusted proxy and audit rows record no IP. Set it only after confirming every trusted proxy overwrites or appends `X-Forwarded-For`.
- **1.11.1: `HTTP_HEADER_READ_TIMEOUT_SECS` (default 10)** also closes idle HTTP/1 keep-alive connections, so a reverse proxy that pools upstream connections should use an idle timeout below it ([#4665](https://github.com/artifact-keeper/artifact-keeper/issues/4665)).
- **1.11.1: public Remotes with upstream credentials are refused** with `400 PUBLIC_REMOTE_UPSTREAM_CREDENTIALS` unless `allow_public_with_upstream_credentials: true` ([#4662](https://github.com/artifact-keeper/artifact-keeper/issues/4662)). Existing ones keep working.
- **1.11.1: the generic download route answers anonymous requests with `401`** instead of `404` and accepts an API token as the Basic password ([#4654](https://github.com/artifact-keeper/artifact-keeper/issues/4654)).
- **1.11.1: an expired CI OIDC assertion is refused with `401`**, and server-signed tokens are validated without leeway ([#4663](https://github.com/artifact-keeper/artifact-keeper/issues/4663)).
- **1.11.1: repository-scoped admin tokens get `403` on the admin download and stats endpoints** ([#4550](https://github.com/artifact-keeper/artifact-keeper/issues/4550)).
- **1.11.1: the dependency scanner queries OSV for the scanned package itself**, so leaf packages can gain findings and gates can start blocking them ([#4669](https://github.com/artifact-keeper/artifact-keeper/issues/4669)).
- **1.11.2: a self-run trivy server must move to 0.76.0 together with the backend**, or scanning stops ([#4712](https://github.com/artifact-keeper/artifact-keeper/issues/4712)). The scanner adapter refuses to scan unless its bundled client and the server report the same trivy release.
- **1.11.2: database outages answer `503` with `Retry-After: 1`**, not `401` or `500` ([#4750](https://github.com/artifact-keeper/artifact-keeper/issues/4750), [#4756](https://github.com/artifact-keeper/artifact-keeper/issues/4756), [#4765](https://github.com/artifact-keeper/artifact-keeper/issues/4765)). Alerts that counted `401`s or `500`s during outages will see `503`s.
- **1.11.2: logs lose ANSI colour codes by default** (`LOG_ANSI=auto`, [#4674](https://github.com/artifact-keeper/artifact-keeper/issues/4674)), and OCI metrics carry route templates instead of `path="unmatched"` ([#4676](https://github.com/artifact-keeper/artifact-keeper/issues/4676)).
- **1.11.2: audit retention now runs hourly**; an unsaved period deletes nothing ([#4718](https://github.com/artifact-keeper/artifact-keeper/issues/4718)).
- **1.11.4: concurrent uploads to one path agree on one winner; the rest get `409`** ([#4832](https://github.com/artifact-keeper/artifact-keeper/issues/4832)). **SAML responses with a DOCTYPE or a non-predefined entity are refused** (GHSA-cp5x-hq47-4mg3). **Removing `LDAP_*` variables disables the env-seeded LDAP provider**, and setting them again does not re-enable it ([#4857](https://github.com/artifact-keeper/artifact-keeper/issues/4857)). **Whitespace inside SAML values is kept as signed instead of trimmed**, which can change group mappings that relied on trimming ([#4827](https://github.com/artifact-keeper/artifact-keeper/issues/4827)). **Plugin git fetches now honour `HTTP_PROXY` / `HTTPS_PROXY`** and `CUSTOM_CA_CERT_PATH`, so on a host with a proxy configured they go through it (GHSA-p28r-8m4q-w9pg).
- **1.11.5: a hosted Maven coordinate whose publish failed now answers `404`** instead of serving the orphaned bytes ([#4837](https://github.com/artifact-keeper/artifact-keeper/issues/4837)).
- **1.11.8: chunked uploads apply storage quotas and the upload quarantine hold** ([#5003](https://github.com/artifact-keeper/artifact-keeper/issues/5003)), and **an LDAP web login no longer reactivates a deactivated account** ([#4933](https://github.com/artifact-keeper/artifact-keeper/issues/4933)).
- **1.11.9: a virtual conda channel's allowlist applies to hosted members too** ([#5055](https://github.com/artifact-keeper/artifact-keeper/issues/5055)). Hosted packages not on the list disappear from the channel. Add them to the allowlist, or set `"scope": "remote_only"` on `PUT /api/v1/repositories/{key}/allowlist` to keep the old behaviour.
- **1.11.10: `test-upstream` refuses an upstream URL the validation rejects with `400`**, and the probe and curation sync go through each Remote's egress proxy ([#5079](https://github.com/artifact-keeper/artifact-keeper/issues/5079), [#5089](https://github.com/artifact-keeper/artifact-keeper/issues/5089)).

## Highlights

### Security

- **Advisories fixed in 1.11.0** ([#4588](https://github.com/artifact-keeper/artifact-keeper/issues/4588)): GHSA-mvmh-g8wm-r3cp (eight mutation endpoints without a repository action check), GHSA-gvhj-8vg9-358g (scan configuration without `write:repositories`), GHSA-2mfv-xg68-gq4p (download tickets ignoring the minting credential's restriction), GHSA-59mx-6fq9-pp9p (image-build pip requirement injecting a `RUN` instruction past `AK_IMAGE_BUILD_ALLOW_RUN=false`), GHSA-9f9r-c4w8-rjv9 (stalled uploads starving health probes) and GHSA-24rf-2gv2-j47c (upstream credentials sent to any host an index named). See **Upgrading** for what each refuses.
- **Tokens and access control.** Artifact label writes need `write` ([#4193](https://github.com/artifact-keeper/artifact-keeper/issues/4193)); bulk promotion applies the quality gate and CVE/licence policy per item ([#3979](https://github.com/artifact-keeper/artifact-keeper/issues/3979)); the CI OIDC exchange no longer merges principals across issuers or reactivates a deactivated account ([#4032](https://github.com/artifact-keeper/artifact-keeper/issues/4032)). `/v2/token` is rate limited on its own bucket, `RATE_LIMIT_TOKEN_EXCHANGE_PER_WINDOW` (default 300), so `podman push` plus cosign no longer exhausts the login budget ([#4020](https://github.com/artifact-keeper/artifact-keeper/issues/4020), [#4558](https://github.com/artifact-keeper/artifact-keeper/issues/4558)). Promotion history and release targets take the repository read gate ([#4418](https://github.com/artifact-keeper/artifact-keeper/issues/4418), [#4473](https://github.com/artifact-keeper/artifact-keeper/issues/4473)). A repository the caller cannot read now answers byte-for-byte like one that does not exist ([#4498](https://github.com/artifact-keeper/artifact-keeper/issues/4498)). Git LFS batch responses carry the caller's credentials and are `no-store` ([#4570](https://github.com/artifact-keeper/artifact-keeper/issues/4570)). - **Remote filters**: include and exclude patterns for what a Remote requests upstream ([#4399](https://github.com/artifact-keeper/artifact-keeper/issues/4399)); npm virtuals can isolate hosted names from upstream ([#3767](https://github.com/artifact-keeper/artifact-keeper/issues/3767)).
- **`record_only` scan-on-proxy action** that records findings without blocking ([#3645](https://github.com/artifact-keeper/artifact-keeper/issues/3645)).
- **Proxy download statistics** that cover pull-through traffic and survive cache eviction ([#3844](https://github.com/artifact-keeper/artifact-keeper/issues/3844), [#4539](https://github.com/artifact-keeper/artifact-keeper/issues/4539)).

### Known issues at 1.11.0

These were reproduced on 1.10.2 and tracked in [#4593](https://github.com/artifact-keeper/artifact-keeper/issues/4593); each refuses access rather than granting it. A `global` permission grant gives no repository access (grant on the repository or project instead). A service account's API token does not grant access on its own; the account needs its own permission. The generic download route answered anonymous requests with `404` and no challenge, fixed in 1.11.1 ([#4654](https://github.com/artifact-keeper/artifact-keeper/issues/4654)). GNU wget 1.25 aborts on the `401` from private format routes; use `wget --auth-no-challenge` or `curl -u`.

- **Logs and detection.** `LOG_ANSI` (default `auto`), richer `LOG_FORMAT=json` fields ([#4674](https://github.com/artifact-keeper/artifact-keeper/issues/4674)), new metrics for rate limiting, SSRF blocks, auth failures and proxy verdicts ([#4676](https://github.com/artifact-keeper/artifact-keeper/issues/4676), [#4677](https://github.com/artifact-keeper/artifact-keeper/issues/4677), [#4642](https://github.com/artifact-keeper/artifact-keeper/issues/4642), [#4711](https://github.com/artifact-keeper/artifact-keeper/issues/4711), [#4549](https://github.com/artifact-keeper/artifact-keeper/issues/4549)), and a trusted gateway's `X-Request-ID` as the correlation ID ([#4677](https://github.com/artifact-keeper/artifact-keeper/issues/4677)).
- **Short upstream bodies answer `502 UPSTREAM_SHORT_BODY`** instead of dropping the connection ([#4759](https://github.com/artifact-keeper/artifact-keeper/issues/4759)); an IdP without `id_token` gets `502 OIDC_NO_ID_TOKEN` ([#4699](https://github.com/artifact-keeper/artifact-keeper/issues/4699)), and the OIDC code exchange now sends configured scopes, which Entra needs.
- **OIDC `redirect_uri` follows only trusted forwarding headers** ([#4143](https://github.com/artifact-keeper/artifact-keeper/issues/4143)).
- **Conan files on cloud storage go to repository-scoped keys** ([#4694](https://github.com/artifact-keeper/artifact-keeper/issues/4694)).
- **Audit retention runs hourly; an unsaved period deletes nothing** ([#4718](https://github.com/artifact-keeper/artifact-keeper/issues/4718)). `POST /api/v1/admin/cleanup` at `0` used to delete every audit row.
- **Postgres TCP keepalives and startup connect retries** ([#4549](https://github.com/artifact-keeper/artifact-keeper/issues/4549)), disabled with `DATABASE_TCP_KEEPALIVES=false`.
- **The setup gate concerns only the built-in `admin`** ([#4634](https://github.com/artifact-keeper/artifact-keeper/issues/4634)).
- **Other.** `PLUGINS_ENABLED`, `HTTP_LISTEN_BACKLOG`, Git LFS following `MAX_UPLOAD_SIZE` ([#4595](https://github.com/artifact-keeper/artifact-keeper/issues/4595)), `npm unpublish` ([#4025](https://github.com/artifact-keeper/artifact-keeper/issues/4025)), proxy-cache integrity healing for zero-byte or truncated entries ([#4630](https://github.com/artifact-keeper/artifact-keeper/issues/4630), [#4758](https://github.com/artifact-keeper/artifact-keeper/issues/4758)), and replication of npm, Go and re-uploaded artifacts ([#4643](https://github.com/artifact-keeper/artifact-keeper/issues/4643), [#4658](https://github.com/artifact-keeper/artifact-keeper/issues/4658)).
