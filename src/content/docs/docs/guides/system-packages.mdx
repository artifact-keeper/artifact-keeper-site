Artifact Keeper provides native repository support for major Linux package formats including Debian/APT, RPM/YUM/DNF, and Alpine/APK.

:::note[Ports and authentication]
The examples use `localhost:30080`, the HTTP port Caddy serves in the stock Docker Compose stack from the [Quickstart](/docs/getting-started/quickstart). Use `:8080` only if you expose the backend directly. Uploads use HTTP basic auth; an API token works as the password (`-u username:$TOKEN`). The token needs the `write:artifacts` scope.
:::

:::caution[Package files are write-once]
Each package file name can be uploaded to a repository once. Uploading the same file name again returns **HTTP 409 Conflict** and the stored file is kept, even if the new bytes differ. To ship a change, bump the version or release (for example `-1` to `-2` for RPM, `-r0` to `-r1` for Alpine) rather than re-uploading. Rebuilt packages are generally not byte-identical (rpmbuild output, for instance, is not reproducible by default), so a rebuilt "same" package is a different file.
:::

:::note[The `ak` CLI]
The `ak` CLI has no format-aware publish command. `ak artifact push <repo> <file>` uploads through the generic artifact API (`PUT /api/v1/repositories/{key}/artifacts/{path}`), not through the Debian, RPM or Alpine routes below, so use the native routes shown in each section to publish system packages.
:::

## Debian / APT

Artifact Keeper provides a full Debian package repository compatible with `apt`, `apt-get`, and `dpkg`.

### Endpoint

```
http://localhost:30080/debian/{repo}
```

### Repository Key

```
debian
```

### Configuration

Add the Artifact Keeper repository to your APT sources:

```bash
# Add repository to sources.list.d
echo "deb [trusted=yes] http://localhost:30080/debian/stable main" | \
  sudo tee /etc/apt/sources.list.d/artifact-keeper.list

# Update package index
sudo apt update
```

### GPG Key Import

For signed repositories, import the GPG key from `GET /debian/{repo_key}/gpg-key.asc`:

```bash
# Download and add GPG key
curl -fsSL http://localhost:30080/debian/stable/gpg-key.asc | \
  sudo gpg --dearmor -o /etc/apt/trusted.gpg.d/artifact-keeper.gpg

# Configure with signed repository (legacy sources.list format)
echo "deb [signed-by=/etc/apt/trusted.gpg.d/artifact-keeper.gpg] http://localhost:30080/debian/stable main" | \
  sudo tee /etc/apt/sources.list.d/artifact-keeper.list

sudo apt update
```

#### DEB822 .sources Format

Modern APT (2.4+) prefers the DEB822 `.sources` format over `sources.list` entries. Point `Signed-By` at the same `gpg-key.asc` endpoint, either fetched ahead of time or referenced directly:

```bash
# Fetch the key once, keyring is referenced by path
curl -fsSL http://localhost:30080/debian/stable/gpg-key.asc | \
  sudo gpg --dearmor -o /usr/share/keyrings/artifact-keeper.gpg

sudo tee /etc/apt/sources.list.d/artifact-keeper.sources <<'EOF'
Types: deb
URIs: http://localhost:30080/debian/stable
Suites: main
Components: main
Signed-By: /usr/share/keyrings/artifact-keeper.gpg
EOF

sudo apt update
```

Both formats are supported side by side; use whichever your distribution's APT version and configuration management expect.

### Repository Metadata Fields

The `Release` file's `Origin`, `Label`, `Version`, and `Description` fields are configurable per repository, read back from `repository_config`:

| Field | Config Key | Description |
|-------|-----------|--------------|
| `apt_origin` | `apt_origin` | `Origin` field in the `Release` file (default: `artifact-keeper`) |
| `apt_label` | `apt_label` | `Label` field in the `Release` file (default: `artifact-keeper`) |
| `apt_release_version` | `apt_release_version` | `Version` field. Omitted from `Release` when unset. |
| `apt_description` | `apt_description` | `Description` field. Omitted from `Release` when unset. |

Set them via the repository update endpoint:

```bash
curl -X PUT http://localhost:30080/api/v1/repositories/stable \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "apt_origin": "Acme Corp",
    "apt_label": "Acme Stable",
    "apt_release_version": "2026.08",
    "apt_description": "Acme internal Debian repository"
  }'
```

### Publishing Packages

Upload `.deb` packages with the native Debian routes. The file name must follow `{name}_{version}_{arch}.deb` and match the package's control data.

```bash
# PUT into the pool: /debian/<repo-key>/pool/<component>/<path>/<file>
curl -u "username:$TOKEN" -T mypackage_1.0.0_amd64.deb \
  http://localhost:30080/debian/stable/pool/main/m/mypackage/mypackage_1.0.0_amd64.deb

# Or POST the raw body (not multipart) to /upload; the file name comes from
# X-Filename or Content-Disposition, and the package goes into the main component
curl -u "username:$TOKEN" -X POST --data-binary @mypackage_1.0.0_amd64.deb \
  -H 'X-Filename: mypackage_1.0.0_amd64.deb' \
  http://localhost:30080/debian/stable/upload
```

The server updates the repository indices after the upload. Uploading the same file name again returns HTTP 409.

### Installing Packages

Once configured, install packages using standard APT commands:

```bash
# Install package
sudo apt install mypackage

# Install specific version
sudo apt install mypackage=1.0.0

# Search for packages
apt search mypackage

# Show package information
apt show mypackage
```

### Multiple Distributions

Support multiple Debian distributions:

```bash
# Ubuntu focal
echo "deb [trusted=yes] http://localhost:30080/debian/ubuntu-focal main" | \
  sudo tee /etc/apt/sources.list.d/artifact-keeper.list

# Debian bullseye
echo "deb [trusted=yes] http://localhost:30080/debian/debian-bullseye main" | \
  sudo tee /etc/apt/sources.list.d/artifact-keeper.list
```

## RPM / YUM / DNF

Artifact Keeper provides RPM repository support compatible with `yum`, `dnf`, and `zypper`.

:::note[RPM proxy hardening (v1.5.0)]
RPM remote/proxy repositories carry Phase-1 SSRF and integrity hardening (#2354):

- **Connect-time private-IP validation** on RPM upstreams — the upstream is
  re-validated against the SSRF policy at connect time, not just at creation.
- **RPM cache classification** distinguishes cacheable content from metadata.
- **Content-integrity verification** of fetched RPM content.
- **Mirrorlist/metalink rejection** — an RPM remote upstream must be a concrete
  `baseurl` (e.g. `.../BaseOS/x86_64/os/`), not a `mirrorlist`/`metalink` URL.

The standard SSRF toggles apply: private-network upstreams require explicitly
opting in via `AK_SSRF_ALLOW_PRIVATE_CIDRS`, and cloud-metadata, loopback, and
link-local addresses stay blocked regardless.
:::

### Endpoint

```
http://localhost:30080/rpm/{repo}
```

### Repository Key

```
rpm
```

### Configuration

Create a repository configuration file:

```bash
# For YUM/DNF (RHEL, CentOS, Fedora)
sudo tee /etc/yum.repos.d/artifact-keeper.repo <<EOF
[artifact-keeper]
name=Artifact Keeper Repository
baseurl=http://localhost:30080/rpm/stable
enabled=1
gpgcheck=0
EOF

# For Zypper (openSUSE)
sudo zypper addrepo http://localhost:30080/rpm/stable artifact-keeper
```

### GPG Key Import

For signed repositories:

```bash
# Import GPG key
sudo rpm --import http://localhost:30080/rpm/stable/repodata/repomd.xml.key

# Enable GPG checking
sudo tee /etc/yum.repos.d/artifact-keeper.repo <<EOF
[artifact-keeper]
name=Artifact Keeper Repository
baseurl=http://localhost:30080/rpm/stable
enabled=1
gpgcheck=1
gpgkey=http://localhost:30080/rpm/stable/repodata/repomd.xml.key
EOF
```

### Publishing Packages

Upload `.rpm` packages with the native RPM routes. The file name must follow `{name}-{version}-{release}.{arch}.rpm`.

```bash
# PUT the file; the name in the URL becomes the package file name
curl -u "username:$TOKEN" -T mypackage-1.0.0-1.x86_64.rpm \
  http://localhost:30080/rpm/stable/packages/mypackage-1.0.0-1.x86_64.rpm

# Or POST the raw body (not multipart); the file name comes from
# Content-Disposition (or X-Package-Filename)
curl -u "username:$TOKEN" -X POST --data-binary @mypackage-1.0.0-1.x86_64.rpm \
  -H 'Content-Disposition: attachment; filename="mypackage-1.0.0-1.x86_64.rpm"' \
  http://localhost:30080/rpm/stable/upload
```

A successful upload returns HTTP 201 with the parsed package metadata (`name`, `version`, `release`, `arch`, `sha256`, `size`). The server regenerates `repodata/` right after the upload, so no `createrepo_c` step is needed. Uploading the same file name again returns HTTP 409.

### Installing Packages

Install packages using YUM or DNF:

```bash
# YUM (RHEL 7, CentOS 7)
sudo yum install mypackage

# DNF (RHEL 8+, CentOS 8+, Fedora)
sudo dnf install mypackage

# Install specific version
sudo dnf install mypackage-1.0.0

# Search for packages
sudo dnf search mypackage

# Show package information
sudo dnf info mypackage
```

### Zypper (openSUSE)

For openSUSE systems using Zypper:

```bash
# Refresh repositories
sudo zypper refresh

# Install package
sudo zypper install mypackage

# Search for packages
sudo zypper search mypackage
```

## Alpine / APK

Artifact Keeper provides Alpine package repository support for `apk`.

### Endpoint

```
http://localhost:30080/alpine/{repo}
```

### Repository Key

```
alpine
```

### Configuration

Add the repository to your APK configuration:

```bash
# Add repository (unsigned): /alpine/<repo-key>/<branch>/<repository>
echo "http://localhost:30080/alpine/alpine-local/v3.18/main" | \
  sudo tee -a /etc/apk/repositories

# Update package index
sudo apk update
```

### Repository Signing

For signed repositories, import the public key:

```bash
# Download public key
curl -fsSL http://localhost:30080/alpine/alpine-local/v3.18/keys/artifact-keeper.rsa.pub \
  -o /etc/apk/keys/artifact-keeper.rsa.pub

# Add signed repository
echo "http://localhost:30080/alpine/alpine-local/v3.18/main" | \
  sudo tee -a /etc/apk/repositories

sudo apk update
```

### Publishing Packages

Upload `.apk` packages with the native Alpine routes. Packages are stored per branch, repository and architecture, matching the path `apk` reads the index from:

```bash
# PUT to /alpine/<repo-key>/<branch>/<repository>/<arch>/<file>
curl -u "username:$TOKEN" -T mypackage-1.0.0-r0.apk \
  http://localhost:30080/alpine/alpine-local/v3.18/main/x86_64/mypackage-1.0.0-r0.apk

# Or POST the raw body (not multipart) to /upload; branch, repository and arch
# come from headers and default to edge, main and x86_64
curl -u "username:$TOKEN" -X POST --data-binary @mypackage-1.0.0-r0.apk \
  -H 'Content-Disposition: attachment; filename="mypackage-1.0.0-r0.apk"' \
  -H 'X-Alpine-Branch: v3.18' -H 'X-Alpine-Repository: main' -H 'X-Alpine-Arch: x86_64' \
  http://localhost:30080/alpine/alpine-local/upload
```

Uploading the same file name again returns HTTP 409.

### Installing Packages

Install packages using APK:

```bash
# Install package
sudo apk add mypackage

# Install specific version
sudo apk add mypackage=1.0.0-r0

# Search for packages
apk search mypackage

# Show package information
apk info mypackage
```

### Multiple Alpine Versions

Support multiple Alpine versions:

```bash
# Alpine 3.18
echo "http://localhost:30080/alpine/alpine-local/v3.18/main" | \
  sudo tee -a /etc/apk/repositories

# Alpine 3.19
echo "http://localhost:30080/alpine/alpine-local/v3.19/main" | \
  sudo tee -a /etc/apk/repositories
```

## OPKG

An `opkg` repository format exists, but there is currently no native OPKG feed endpoint: the server does not serve `/opkg/...` URLs or generate a `Packages` index, so `opkg update` cannot use an Artifact Keeper repository as a feed. To store `.ipk` files, use a [Generic repository](/docs/guides/more-formats/) and the generic artifact API, and generate the feed index with your build tooling.

## Integration with CI/CD

### GitHub Actions Example

Build and publish packages automatically:

```yaml
name: Build and Publish Package
on: [push]

jobs:
  build-deb:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build Debian package
        run: |
          dpkg-buildpackage -us -uc -b
          mv ../mypackage_*.deb .

      - name: Publish to Artifact Keeper
        run: |
          curl -fsS -u ${{ secrets.REGISTRY_USERNAME }}:${{ secrets.REGISTRY_PASSWORD }} \
            -X POST --data-binary @mypackage_1.0.0_amd64.deb \
            -H 'X-Filename: mypackage_1.0.0_amd64.deb' \
            https://registry.example.com/debian/stable/upload

  build-rpm:
    runs-on: ubuntu-latest
    container: fedora:latest
    steps:
      - uses: actions/checkout@v4

      - name: Install build tools
        run: dnf install -y rpm-build rpmdevtools

      - name: Build RPM package
        run: |
          rpmdev-setuptree
          rpmbuild -ba mypackage.spec
          mv ~/rpmbuild/RPMS/x86_64/*.rpm .

      - name: Publish to Artifact Keeper
        run: |
          for rpm in *.rpm; do
            curl -fsS -u ${{ secrets.REGISTRY_USERNAME }}:${{ secrets.REGISTRY_PASSWORD }} \
              -T "$rpm" "https://registry.example.com/rpm/stable/packages/$rpm"
          done
```

### GitLab CI Example

```yaml
build:deb:
  stage: build
  image: debian:bullseye
  script:
    - apt-get update && apt-get install -y build-essential devscripts
    - dpkg-buildpackage -us -uc -b
    - mv ../mypackage_*.deb .
  artifacts:
    paths:
      - mypackage_*.deb

publish:deb:
  stage: deploy
  script:
    - |
      curl -fsS -u $REGISTRY_USERNAME:$REGISTRY_PASSWORD \
        -X POST --data-binary @mypackage_1.0.0_amd64.deb \
        -H 'X-Filename: mypackage_1.0.0_amd64.deb' \
        https://registry.example.com/debian/stable/upload
  dependencies:
    - build:deb
  only:
    - main
```

Because package files are write-once, a pipeline that re-runs on the same version gets HTTP 409 from the upload. Bump the package version or release for each build that should be published.

### Jenkins Pipeline Example

```groovy
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                sh 'dpkg-buildpackage -us -uc -b'
                sh 'mv ../mypackage_*.deb .'
            }
        }

        stage('Publish') {
            steps {
                withCredentials([usernamePassword(
                    credentialsId: 'artifact-keeper',
                    usernameVariable: 'USERNAME',
                    passwordVariable: 'PASSWORD'
                )]) {
                    sh '''
                        curl -fsS -u $USERNAME:$PASSWORD \
                          -X POST --data-binary @mypackage_1.0.0_amd64.deb \
                          -H 'X-Filename: mypackage_1.0.0_amd64.deb' \
                          https://registry.example.com/debian/stable/upload
                    '''
                }
            }
        }
    }
}
```

## Troubleshooting

### Repository Not Found

If packages are not visible after publishing:

```bash
# Verify repository metadata was generated
curl http://localhost:30080/debian/stable/dists/main/Release
curl http://localhost:30080/rpm/stable/repodata/repomd.xml
curl -o /dev/null -w '%{http_code}\n' \
  http://localhost:30080/alpine/alpine-local/v3.18/main/x86_64/APKINDEX.tar.gz
```

Metadata is regenerated by the server on upload; there is no separate reindex step. If a package is missing, check that the upload returned HTTP 201 (not 409 for an existing file name, or 4xx for a file name that does not match the package metadata).

### GPG Verification Failures

If package installation fails with GPG errors:

```bash
# Debian/Ubuntu: verify key is imported
apt-key list
gpg --list-keys

# RHEL/CentOS: verify key is imported
rpm -q gpg-pubkey --qf '%{NAME}-%{VERSION}-%{RELEASE}\t%{SUMMARY}\n'

# Alpine: verify key exists
ls -la /etc/apk/keys/
```

### Architecture Mismatch

Ensure packages match your system architecture:

```bash
# Check system architecture
uname -m
dpkg --print-architecture  # Debian/Ubuntu
rpm -q --qf '%{ARCH}\n' bash  # RHEL/CentOS

# Verify package architecture
dpkg-deb -I mypackage.deb | grep Architecture
rpm -qip mypackage.rpm | grep Architecture
```

### Connection Issues

If unable to reach the repository:

```bash
# Test connectivity
curl -I http://localhost:30080/debian/stable/

# Check DNS resolution
nslookup registry.example.com

# Test with verbose output
apt update -o Debug::Acquire::http=true
yum install mypackage -v
```

### Permission Denied

For authentication errors:

```bash
# Verify credentials
curl -u username:password http://localhost:30080/api/v1/auth/me

# Check the repository exists and is visible to you
curl -u username:password http://localhost:30080/api/v1/repositories/stable

# Use token authentication
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:30080/api/v1/repositories/stable
```

## Best Practices

### Version Naming

Follow distribution conventions:

```bash
# Debian: package_version_architecture.deb
mypackage_1.0.0_amd64.deb
mypackage_1.0.0-1_arm64.deb

# RPM: package-version-release.architecture.rpm
mypackage-1.0.0-1.x86_64.rpm
mypackage-1.0.0-2.el8.aarch64.rpm

# Alpine: package-version-release.apk
mypackage-1.0.0-r0.apk
mypackage-1.0.0-r1.apk
```

### Repository Organization

Organize repositories by distribution and version:

```bash
# Debian
/debian/ubuntu-20.04
/debian/ubuntu-22.04
/debian/debian-11
/debian/debian-12

# RPM
/rpm/el7
/rpm/el8
/rpm/el9
/rpm/fedora-38

# Alpine
/alpine/v3.18
/alpine/v3.19
```

### Package Metadata

Include comprehensive package metadata:

- Clear package descriptions
- Accurate dependency declarations
- Changelog entries
- Maintainer information
- License information

### Testing Before Production

Always test packages in a staging environment:

```bash
# Use separate repositories for testing
/debian/stable        # Production
/debian/testing       # Pre-production testing
/debian/unstable      # Development builds
```

## Remote & Virtual Repositories

Use Artifact Keeper as a pull-through cache for public system package repositories or aggregate multiple package sources.

Remote proxy and virtual repository support is available for all system package formats: RPM (yum/dnf), Debian (apt), and Alpine (apk).

For RPM specifically, remote/proxy repositories are hardened as of v1.5.0
(#2354): connect-time private-IP SSRF validation, RPM cache classification,
content-integrity verification of fetched content, and rejection of
`mirrorlist`/`metalink` upstreams (point the upstream at a concrete resolved
`baseurl` instead). Reaching a private-network upstream still requires opting in
via `AK_SSRF_ALLOW_PRIVATE_CIDRS`.

### Pull-Through Cache Examples

```bash
# RPM - cache from CentOS/EPEL
curl -X POST http://localhost:30080/api/v1/repositories \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "key": "rpm-remote",
    "name": "RPM Remote",
    "format": "rpm",
    "repo_type": "remote",
    "upstream_url": "https://mirror.centos.org/centos/8/BaseOS/x86_64/os"
  }'

# Debian - cache from Ubuntu archive
curl -X POST http://localhost:30080/api/v1/repositories \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "key": "deb-remote",
    "name": "Debian Remote",
    "format": "debian",
    "repo_type": "remote",
    "upstream_url": "http://archive.ubuntu.com/ubuntu"
  }'

# Alpine - cache from Alpine Linux
curl -X POST http://localhost:30080/api/v1/repositories \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "key": "alpine-remote",
    "name": "Alpine Remote",
    "format": "alpine",
    "repo_type": "remote",
    "upstream_url": "https://dl-cdn.alpinelinux.org/alpine"
  }'
```

### Virtual Repositories

Combine internal and cached packages behind a single source for each format. See the [Remote & Virtual Repositories](/docs/advanced/remote-virtual) guide for full details on setting up virtual repositories, cache TTL, and priority ordering.
